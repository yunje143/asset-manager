# Functional Requirements
- 各資産（物件・部屋）ごとの収支、利回り、償却残年数の一覧表示。
- 全資産を統合した合計利回りおよび今月のキャッシュフローのダッシュボード。
- マンション、テナント、民泊（宿）のハイブリッド運用に対応。

# Calculation Logic

## 1. キャッシュフロー (CF)
- **賃貸・テナント**:
  `CF = 家賃収入 - 運営諸経費 - ローン返済額(元本+利息)`
- **民泊 (Stay)**:
  `CF = (宿泊料 * 稼働日数) + 清掃費徴収額 - 清掃外注費 - 変動経費 - 固定経費 - ローン返済額`

## 2. 帳簿上の利益 (Accounting Profit)
`利益 = 収入 - 運営諸経費 - ローン利息 - 減価償却費`

## 3. 実質利回り (Net Yield)
$$実質利回り = \frac{\sum_{12ヶ月} (家賃収入) - \sum_{12ヶ月} (運営諸経費)}{\text{物件取得価格}} \times 100$$
※運営諸経費：管理費、固定資産税、保険料、修繕費（その年分）。

## 4. 将来予測キャッシュフロー (Multi-Timeline Projection)
ユーザーが選択した期間に応じて、現在のポートフォリオが未来に生み出すキャッシュフローをシミュレーションする。

### 予測スパンの定義
アプリ内では以下の3つの時間軸を切り替えて表示可能とする。
1. **短期ビュー (1年間 / 月次集計)**: 直近12ヶ月の月々の資金繰り・季節性の可視化。
2. **中期ビュー (3〜5年間 / 年次集計)**: リース満了や中期修繕、再投資余力の可視化。
3. **長期ビュー (10〜20年間 / 年次集計)**: 社債の満期償還、不動産の大規模修繕、ローン残高の推移の可視化。

### 複数資産の統合ルール（将来の拡張）
- 各収益（家賃、利息、リース料）および費用（修繕費、ローン返済）は、それぞれの「発生スケジュール（終了月・満期月）」に従ってタイムライン上にマッピングされ、合算してポートフォリオ全体の推移を描画する。

# Detailed Rules
- **自動生成**: 物件種別に基づき、月初のタイミングで「入金待ち」レコードを自動作成する機能。
- **バックアップ**: ユーザーが `.db` ファイルをコピーして保存・復元できること。

# Future Extensibility & Generalization (将来の拡張性と汎用性)

## 1. 多様な資産への対応
- **抽象化設計**: 
  現在の `units (部屋)` は将来的に「収益発生源 (Earning Source)」として抽象化される。社債の「銘柄」やファンドの「契約」も同様のデータ構造で管理する。
- **異周期への対応**: 
  家賃（月次）だけでなく、半年毎の利息、不定期な分配金も `incomes` テーブルの `date` 管理により一元化する。

## 2. 汎用インカム・ワークフロー
- **Pending-First原則**: 
  すべての収益はまず `pending` 状態で登録（または自動生成）され、ユーザーの確認（消込）を経て `completed` となる。
- **予測可能性**: 
  `pending` レコードを参照することで、将来（最大12ヶ月先まで）の予定キャッシュフローをグラフ化可能とする。

## 3. CSVインポートの標準化
- **マッパーの共通化**: 
  Airbnb、銀行の入出金明細、証券会社の取引履歴など、異なる形式のCSVを `incomes` / `expenses` に変換するためのプラグイン構造を想定する。

# Non-Functional Requirements (Update)

## データ保護とバックアップ
- **ローカル完結**: 外部サーバーに依存せず、ユーザーの端末内のみでデータ管理を完結させる。
- **レジリエンス**: 
  - 万が一メインDBが破損した場合でも、バックアップフォルダから最新の `.db` を差し替えるだけで復旧可能とする。
- **エクスポート機能**: 
  - UI上の設定画面から、任意の保存先に現在のDB状態を `.db` 形式で出力（エクスポート）できる。
