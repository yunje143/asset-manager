# 要件定義

SPEC.md（元仕様書）を基に、実装にあたって確定した要件をまとめる。

## 1. 概要

不動産（テナント）・社債・株式の取引履歴と市場データ（yfinance）を統合し、資産状況とカテゴリ別推移を可視化する Streamlit BI ツール。Docker コンテナ化して **Cloud Run** にデプロイし、Cloudflare Access で許可した Google アカウントのみアクセス可能にする。

## 2. 画面

サイドバーのナビゲーションは `st.navigation()` で日本語タイトル＋Material Symbols アイコン（`:material/xxx:`）を明示的に設定している（`pages/` のファイル名からの自動生成には頼らない。詳細は `docs/architecture.md`）。

| 画面（ファイル） | ナビ表示 | 内容 |
| :--- | :--- | :--- |
| `pages/total.py` | :material/dashboard: 総合 | 収支サマリー4指標（純資産評価額・総収入・総費用・純額、いずれもスパークライン付き`st.metric`）、資産配分ドーナツ、資産構成の積み上げ推移、資金の流れSankey（`st-echarts`） |
| `pages/real_estate.py` | :material/apartment: 不動産 | 月次収入・費用の棒グラフ、累計純収支（資産状況の推移）ライン、物件別収入vs費用の横棒グラフ（Altair / `st.line_chart`） |
| `pages/bond.py` | :material/account_balance: 社債 | 簿価合計・累計受取クーポン・期間変化・簿価推移ライン、償還までの残存期間ゲージ、銘柄別明細テーブル |
| `pages/stock.py` | :material/trending_up: 株式 | 評価額合計・前日比・前月比・評価額推移ライン、銘柄別ローソク足チャート、銘柄別明細テーブル |

サイドバーの期間フィルター（`1 Month` / `3 Months` / `6 Months` / `12 Months` / `24 Months` / `All Time`）は全画面で共有され、推移グラフと期間比較デルタに反映される。

## 3. 実装にあたり確定した設計判断

SPEC.md には記載がない、または解釈が分かれる箇所について、実装前に以下を確定した。

### 3.1 社債は簿価表示のみ（時価評価しない）

yfinance は個別社債（相対取引の債券）の価格を現実的に取得できない。そのため：
- 社債の評価額・評価損益カラムは実装しない
- 社債は取得コストの累計（簿価）のみで表示する
- yfinance への銘柄取得リクエストは株式カテゴリのティッカーのみに限定する

### 3.2 通貨換算はしない（全取引JPY建て前提）

`transactions.amount` と yfinance の `close_price`（米国株ティッカーは USD 建て）の通貨換算ロジックは実装しない。全ての取引額は JPY 建てとして扱う簡略化を採用している。将来 USD 建て資産の正確な評価が必要になった場合は、`market_data.py` に FX レート取得・換算処理を追加する必要がある。

### 3.3 「残高（点）」と「フロー（期間内の量）」を明確に分ける

保有数量・取得コスト（簿価）・評価額・評価損益・Total画面の**純資産評価額**・ドーナツの内訳・資産構成の推移は、常に**全取引**を対象にした残高（point-in-time）であり、期間フィルターの影響を受けない。期間フィルターが影響するのは以下の「推移・フロー」系の指標のみ：
- 月次収入/費用/累計純収支（Real Estate）
- 物件別収入 vs 費用（Real Estate、期間内の取引に限定）
- 簿価推移ライン（Bond）
- 評価額推移ライン（Stock）
- Total画面の総収入・総費用・純額（収入−費用）とそのスパークライン（`calculations.total_monthly_cashflow_trend()`）
- 各画面の `st.metric` の期間比較デルタ（現在値 vs 期間開始時点の値）

Total画面の収支サマリーは意図的にこの2種類を並べている。**純資産評価額**は「今までの累計でいくら資産があるか」という残高、**総収入・総費用・純額**は「選択中の期間内でどれだけお金が動いたか」というフローで、別の情報である（前者は期間フィルターを変えても動かないが、後者は動く）。

`st.metric` の `chart_data` は、データが0件の期間でも `None` ではなく `[0]`（ゼロ1点）を渡している。`None` ↔ リストの間で切り替えると、期間フィルターを変えたときにスパークラインが再描画されない Streamlit 側の挙動があるための回避策（`app.py` 参照）。

### 3.4 `ticker_map` シートの新設・拡張

`transactions` シートには `asset_name` はあるが `ticker` カラムがない（SPEC 3.1 に忠実）。`asset_name → ticker` は取引ごとに変わらない安定した対応関係のため、同一スプレッドシートに `ticker_map` タブを新設し、集計時に結合する。株式・社債で使うカラムが異なる（`docs/database.md` 参照）：
- 株式: `asset_name`, `ticker`
- 社債: `asset_name`, `maturity_date`（償還期限）, `coupon_rate`（表面利率）— 時価評価には使わず、Bond画面の残存期間ゲージ・明細表示にのみ使う付加情報

未登録の株式資産は保有数量・簿価は表示されるが評価額は N/A となる。

### 3.5 ホスティングは Cloud Run に確定、サービスアカウント鍵は発行しない

当初 SPEC.md では Cloud Run / Render / Fly.io を候補としていたが、Google スプレッドシート連携の都合上どのみち GCP プロジェクトが必須であること、また組織ポリシーでサービスアカウントの鍵発行がデフォルト禁止されていた経緯から、**Cloud Run に一本化**した。これにより、サービスアカウントの認証は Application Default Credentials（ADC）で行い、鍵ファイルを一切発行・保管しない構成にできる（詳細は `docs/architecture.md` の「secrets / 認証」を参照）。Render / Fly.io は ADC の恩恵を受けられずキー管理が別途必要になるため、今回の3名規模の個人利用では採用しないこととした。

### 3.6 UI表記は日本語、ナビゲーションは `st.navigation` + Material Symbols アイコン

サイドバーのページ名・各画面の見出しは日本語で統一する（英語表記が混在していたための修正）。ページ切り替えは Streamlit の `pages/` ディレクトリによるファイル名ベースの自動ナビゲーションではなく、`st.navigation()` + `st.Page(title=..., icon=...)` を `app.py` で明示的に構成し、日本語タイトルと `:material/xxx:` 形式の Material Symbols アイコンを付けている。各画面内の `st.header()` / `st.subheader()` にも、内容に対応するアイコンを適度に付与している（詳細は `docs/architecture.md` の「画面ナビゲーション」を参照）。
